# OPC UA 模拟与采集

模拟器提供两条产线、六台设备、24 个测点。信号由固定种子与时间函数生成，可注入坏质量场景；其数值不代表真实工业工况。

采集任务保存端点、节点到测点的映射、发布周期、批量大小和启停意图。监督器读取数据库中的运行任务，每个任务独立建立异步客户端与 DataChange 订阅；通知进入有界内存队列，写入进程按批量大小或时间窗口刷新到 PostgreSQL。

样本保存测点 ID、任务 ID、数值/原始值、源时间、服务端时间、接收时间和质量码。唯一键阻止同源重复样本。最新值和历史趋势沿用同一套资产权限；名称来自资产主数据关联，不用名称替代稳定 ID。

## 状态与恢复

- `desired_state` 是用户启停意图；`connection_state` 是运行观察。二者不能混为一谈。
- 停止后迟到的断连回调不能覆盖停止状态；重新启动后旧清理不能把新意图改回停止。
- 数据库尚未就绪时监督器等待并重试；运行任务异常退出后按已保存的启停意图重新创建，不修改用户意图。
- 写入子任务失败会传回采集任务，并释放订阅与连接；不能仅凭 OPC 连接存在就持续宣称采集正常。
- 容器配置自动重启作为第二层保护，应用内重试才负责数据库启动顺序与运行期恢复。

## 验收

启动模拟任务后检查连接、心跳、接收数、写入数和源时间是否共同推进。停止任务后数值应不再更新；新一轮启动应恢复采集。故障演练在隔离环境进行，不重启日常数据库来制造测试条件。

## 限制

只有一个监督器，没有分布式所有权租约或主备选举。队列只在内存中，队列溢出计数不等于能恢复样本；数据库/进程故障期间未提交的数据可能丢失。尚未实现持久化采集缓冲、历史补采或真实设备安全连接验收。
