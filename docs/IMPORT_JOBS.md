# 持久化历史导入任务

数据库迁移 `b208e4c7a531` 增加持久化任务。处理接口异步接收任务，导入数据仍以整批事务提交。

## 接口与运行方式

- `POST /api/v1/imports/{id}/process` 返回 **202** 和批次信息，表示已接收任务，不是入库完成。
- `GET /api/v1/imports/{id}` 查询批次；`GET /api/v1/imports/{id}/job` 查询最近一次任务及进度。未提交过任务时后者返回 `null`。
- 同一批次相同映射重复提交，在 queued/running/succeeded 状态复用原任务；更换映射返回 409。已失败的批次可以重新提交，创建新任务，旧失败记录仍保存在数据库。
- 所有接口执行角色和工厂范围校验。后台工作进程在开始和数据提交前重新校验提交人的有效性、角色及工厂权限。
- 助手查询未完成批次时明确说明状态，不把仍为零的计数解释为无问题或导入成功。列表工具同时返回 `counts_final`，供模型判断是否能使用最终统计。
- `docker compose up -d import-worker` 启动独立工作进程。先完成数据库迁移，且与 backend 使用同一版本镜像。
- 工作进程只读挂载导入目录；上传与源文件删除仍由 API 管理。排队和处理中均禁止删除源文件。

## 状态与事务

批次：uploaded → queued → processing → completed / failed。
任务：queued → running → succeeded / failed。

任务认领先提交状态。数据、映射与问题行在整批事务中统一提交；进度使用另一条连接提交，含义为“已扫描测量记录”，不是已入库记录。宽表一行多个映射变量计为多条测量记录，因此没有用文件行数制造不准确的进度百分比。

每个批次以 PostgreSQL 会话级 advisory lock 保证同一时刻只有一个工作进程执行。锁与实际处理绑定同一数据库连接，不能把持锁连接提前归还连接池。另有部分唯一索引阻止同一批次同时拥有多个活动任务。

进度最多每两秒更新。`IMPORT_JOB_RECOVERY_SECONDS` 默认 60 秒；新工作进程只考虑心跳过期的运行任务，但必须先取得执行锁。不能只凭心跳过期抢占仍然持锁的旧进程。

## 故障处理

1. 进程被终止：连接关闭后数据库回滚未提交数据并释放锁；等待恢复期后重新读取同一源文件，不是从进度计数断点追加。
2. 数据已经提交，但任务成功标记未写入：新进程发现批次 completed 后只修正任务状态，不再导入。
3. 映射错误、源文件丢失/改变、账号停用或授权撤销：标记失败并保存原因，避免无限重试不可修复错误。
4. 自动中断恢复默认最多三次，可通过 `IMPORT_JOB_MAX_ATTEMPTS` 调整；达到上限需检查原因后手动重试。
5. 读取前核对源文件路径范围及 SHA-256，防止使用与预览不一致的源文件。

这不是无限制的 exactly-once 分布式系统承诺；保障范围是同一 PostgreSQL 数据库及当前文件导入唯一键规则下的批次执行与入库。文件存储和数据库也不是跨资源原子事务。

## 验证

`tests/api/routes/test_import_jobs.py` 覆盖幂等提交、执行锁竞争、处理中断回滚与进度独立提交、提交后确认丢失、恢复上限与手动重试、源文件异常、权限撤销。

其中 SIGKILL 测试启动真实子进程，在其已插入第一条未提交记录后直接杀死进程，确认其他连接看不到部分数据，后续工作进程恢复后仅写入预期记录。测试只能在 `_test` 独立数据库执行，不能手动将测试数据库地址改为业务库。

## 性能复现

容器内执行 `bash scripts/benchmark-import-jobs.sh --reset-import-test-db /data/imports/全新报告目录`。脚本只重建 `app_import_perf_test`，报告目录已存在则拒绝运行；不要修改其数据库隔离保护。对 10,000 行各测三次并交替顺序，对 100,000 行各测一次，比较同版处理器直接调用与持久化任务调用。报告与临时合成文件沿用 IMPORT_STORAGE_DIR，临时文件处理完后清理。

报告区分提交耗时、完整处理耗时、实际入库行数、Python 分配峰值与进程生命周期最大 RSS。队列模式立即调用真实工作函数，不包含轮询等待，不是 HTTP 响应时间。tracemalloc 本身会增加运行成本。测量期间不要同时运行其他本地测试、构建或备份恢复；业务采集等背景负载也需记录。任何污染的运行必须保留并标记，不能挑选最好的一次当总体效果。

追加 `--no-tracemalloc` 可关闭内存分配跟踪，此模式对 10,000 和 100,000 行均各测三次，并交替 sync/queued 顺序；Python 分配峰值返回 null，而不是零。RSS 是整个进程生命周期最大值，不等同于导入函数分配峰值。

批量写入已改为参数列表执行，避免为每批每个单元格重复构造 SQL 表达式绑定树。保留原唯一键冲突处理、RETURNING 入库计数、质量及来源字段；没有跳过校验，也没有把整批事务拆成部分成功。实测与边界见[导入性能对照](IMPORT_PERFORMANCE_20260908.md)。

## 当前限制

- 整批事务仍可能较长；文件内去重键集合随数据量增加。异步化不等于导入吞吐或内存已优化。
- 未实现用户取消、逐行断点续传或多主机文件分发；多主机部署需共享同一源文件存储。
- 每次轮询最多检查 20 个候选任务；当前面向少量工作进程，不宣称支持任意规模调度。
- 旧版本遗留的 processing 批次没有任务记录，不会被盲目自动重新执行，需要人工核查。
- 账号权限在开始与提交前校验，不宣称对毫秒级并发撤权操作有全局线性化保证。
- 不提供生产 SLA。实际部署和后续并发、容量、恢复测试结果需另行记录。
