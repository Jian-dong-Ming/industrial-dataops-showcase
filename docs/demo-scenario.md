# 可复现业务场景：冷却回路扰动

## 三种数据分开看

| 入口 | 数据来源 | 是否表示当前数据库状态 |
|---|---|---|
| `/demo` 场景回放 | 固定种子的离线合成数据 | 否；不读写业务库、不启动OPC任务 |
| `/acquisition` 实时采集 | 当前授权范围内的OPC采集样本 | 是，但任务停止后显示的是最后保存值 |
| `/data-governance` 数据治理 | 明确上传并导入的CSV/XLSX | 是；有文件批次来源，不伪装为OPC采样 |

本项目没有企业设备接入、物理仿真、故障诊断模型、质量预测或自动控制成果。Good是采集质量，不等于产品合格。静态演示字典不覆盖用户实际资产配置。

## 回放如何形成

`backend/app/opcua/catalog.py`是两线六设备24测点的演示目录。`scenario.py`使用固定种子20260911、2秒间隔，生成0–180秒的91帧（2184条测量记录）。固定起点为2026-01-15 08:00:00北京时间，时间不随打开页面改变。文件内容提供SHA-256校验。

三段时间线：

1. 0–60秒之前：两线各自基线波动。
2. 60–120秒之前：仅一号线流量、压力、出口温度受脚本扰动；60–80秒逐步增强，之后保持。90–100秒之前，PUMP_FLOW另有5条坏质量记录。
3. 120–180秒：逐步撤销附加扰动，160秒后仅剩正常周期和噪声。二号线始终不注入这些扰动。

人为设定的流量下降、压力升高、出口温度升高只用于说明多测点观察，不证明管路堵塞或任何真实故障原因。旧名“炉压”是独立教学压力通道，不能解释为真实炉膛压力标准。

图表横轴按真实回放秒数绘制；各图纵轴独立，坏质量记录以红点保留但不连入有效趋势。左侧产线切换可看未注入侧。测点表按设备分组排列。

## 一次完整体验

1. 登录，工作台进入“场景回放”。依次查看正常、异常、恢复片段。
2. 在90秒比较一、二号线流量及质量，说明为什么“值变化”和“质量异常”不能混为一谈。
3. 下载CSV，检查SHA-256及2184条记录；下载本身不改数据库。
4. 若要练习导入，优先使用下面的隔离测试环境。在对应工厂已有24个启用的演示测点时，选择窄表：时间→timestamp、测点编码→tag_code、测量值→value、质量码→quality_code。设备编码不映射。
5. 首次导入、目录未修改且不存在同测点同时间文件样本时，预期2184接受、0拒绝、5条坏质量警告。实际仍以批次结果为准。重复导入会命中去重，不要删历史绕过它。
6. 在AI助手选择已加入场景文档的教学工厂，先用本地检索查询“回放90秒的PUMP_FLOW为什么是坏质量”“二号线为什么能作对照”。涉及当前采集状态时，应明确要求查询实际任务，不从回放动画猜测。

## 知识初始化

`backend/scripts/seed-ai-demo.py`默认只预览，将平台手册和7篇版本化场景说明加入既有OPC_DEMO工厂。明确传入`--confirm`才写入；已有同名文档不覆盖。默认不向任何外部模型发送内容。

向量化必须额外传入`--vectorize-bundled --confirm`并配置向量服务；只发送未被用户改动的内置合成文档，会产生服务调用。关键词回归通过不等于真实模型问答准确率。

## 独立浏览器验收（WSL）

```bash
bash scripts/browser-test-local.sh start
bash scripts/browser-test-local.sh test --project=chromium
bash scripts/browser-test-local.sh stop
```

只使用独立`compose.browser-test.yml`：8201为测试网页、1081为测试邮件，数据库`app_browser_test`在独立容器内存文件系统中，没有宿主数据库端口，也不挂载日常数据卷。停止后测试数据库消失。导入与报告默认放E盘`industrial-dataops-browser-test`，不是日常导入目录。测试账号仅存在该实例，禁止用于生产。

不读取日常`.env.ai`，不自动调用付费模型。浏览器写测试还必须通过服务端的测试模式及实际数据库名检查；指向8200日常实例会拒绝运行，而不是靠前端一个环境变量就允许写入。

注意：镜像缓存仍由Docker Desktop管理；本方案减少测试数据库和报告对C盘的占用，不声称Docker所有文件都已迁移到E盘。

## 证据与边界

后端测试包含确定性、CSV与JSON一致、认证、真实导入计数、6个开发问题的关键词命中、工厂权限隔离及无词命中场景。浏览器专项检查桌面/手机布局、阶段与产线切换、质量标记和CSV哈希。最终通过数以对应提交的完整回归为准，不把测试数量或覆盖率写成模型准确率。

## 真实模型验收与已知限制

`backend/scripts/verify-scenario-live.py --allow-billed-requests --suite core --output <E盘新报告路径>`运行6个场景功能问题；`--suite provenance`运行4个来源与状态复查问题。需先配置模型及向量服务。报告保留原文、引用、工具、用量与语料哈希；结构检查不等于语义准确，默认不写人工准确率。

2026-09-11真实调用发现：模型曾仅凭说明文档回答错误的任务总数。现对明确的中文当前采集任务查询由服务端先执行授权范围内的状态工具，并从工具结果生成数量、状态与累计计数；增加模型跳过工具/编造数字、跨厂排除和非查询措辞测试。该规则不是通用意图识别，其他查询仍使用受限工具循环。

来源判断也加入提示约束：文件格式及协议不能证明真实或合成来源。前轮真实回归发现了全库来源过度概括、误称质量码映射可选和多余场景别名，现补充有限输出校验：可识别的无依据版本标识、全库来源断言及质量映射/警告数矛盾触发一次纠正，仍失败则明确拒答。该校验不覆盖所有自然语言，不能证明每个回答正确。

补强后6个核心真实问题的字段映射、场景含义、任务状态和无依据拒答经逐题复核符合现有证据。4个来源复查问题中，1题因返回no_answer而非期望answered仍保留结构失败；不能仅靠调整评分改成全绿。该题“不因文件名/个人平台而认定合成”的主结论正确，但后续来源核实建议不充分；导入计数、质量码及哈希均不能单独证明企业来源。本平台没有自动数据来源鉴定功能。

使用时仍须对照引用与页面结果，不能代替确定性的导入规则、资产查询、现场诊断或生产决策。要复现本场景的5条质量警告，必须映射quality_code；界面允许不映射不等于本场景可忽略该列。知识列表采用限高滚动区域，保留完整文档与编辑入口，并支持键盘滚动，不因展示篇数变多而无限拉长页面。
